What this is

A fully offline, single-player build of Girl Cafe Gun for preservation and study. The whole game server — a self-contained .NET runtime plus the open-source sssj-new server plus the game's config tables — is packed inside the APK. A small shim starts that server as a local process when the game launches and points the client at http://127.0.0.1:9080, so the client talks to a server running on the same device. Nothing leaves the phone.

This is not affiliated with or endorsed by the game's creators. It ships no game assets — you provide your own from a copy of the official app you own. See Credits & IP.

Since 2026-11-14 the project base is GirlCafeGun-Remake (TypeScript server, chapters 1-16, signed updates). This page describes the C# build, which stays as the source of fixes that are ported there. The phone build on the Remake base is in docs/15-REMAKE-PHONE-BUILD.md.

How it works

  1. Shim libmain.so replaces Unity's tiny JNI entry: on launch it chains the real one (game boots normally), extracts the bundled server, and forks it as its own process (the .NET runtime can't share Unity's il2cpp process).
  2. No root: the runtime .so ship as lib/arm64-v8a/*.so, so Android installs them in the exec-allowed native-library dir; the server runs from there, not the SELinux-blocked data dir.
  3. Offline config patch: the shim patches il2cpp in memory (via /proc/self/mem, in a re-apply loop) so the client uses the local server and the offline-account path.
  4. Airplane mode: the client's "check your network" gate (IsNetworkOk / IsNetworkReachability) is statically patched to always pass, so New Account works with no network at all.

Install (quick)

Requires an arm64 Android emulator — MuMu Player 12 with Root on is easiest — or an arm64 phone, plus adb on your PC.

  1. Get the asset pack (the game files, ~6 GB to play) and unzip it so gcg_offline.apk and assets/ sit next to INSTALL.bat.
  2. Start your emulator / connect your phone.
  3. Double-click INSTALL.bat. It installs the APK, the OBB, syncs the content bundles, and launches the game.

First launch: Terms screen → “Agree to all & start”. At the title (server shows Local) → New Account → play. Full guide: docs/01-PLAY.md.

Build it yourself

Everything original here is MIT. With a stock APK you own, the .NET 10 SDK, and the Android NDK/build-tools:

powershell -File scripts\build-apk.ps1 -OrigApk C:\path\to\base.apk

That publishes the server, bakes the data tar, patches il2cpp, compiles the shim/host, and re-signs the APK. Details: docs/03-BUILD-APK.md.

Limitations & known issues

AreaStatusNotes
Offline play / airplane modeWorks Fresh account, tutorial, story, gacha, shop — all offline. Verified end-to-end.
“Connection error” / still calls the official serverFixed The serverlist config (envir.json) is pointed at the local server statically, so the client never calls online — no runtime race. The airplane network-gate is patched too. Older builds relied on an in-memory patch that could lose the boot race; this one can't.
Missing voice / scenes / artFixed Earlier builds synced only ~380 bundles; this one ships the full set the game references (~4.5 GB) so content isn't missing. Not an install mistake — it was a packaging gap.
Censored Live2D touch / flirting interactionsRestored The global build gates these via a server flag; the installer applies the love.u bypass by default so they run at full level (-NoUncensor to opt out). The animations were never removed from the model — only gated. The base art is identical across regions.
Chinese title buttons (新账号 / 输入账号)Fixed The login prefab (ui/ui_login_prefab.u) now carries English labels (New Account / Enter Account); see docs/05-PHONE-PORT.md. The intro and most text are English.
Background telemetry callsHarmless Bundled analytics SDKs (Crasheye, xgsdk, Firebase) still try to phone home and fail silently offline. They don't block play and nothing reaches them. After many offline launches a backlog can slow boot — clear it with adb shell pm clear … (wipes the local account).
Non-rooted phonesWorks The server needs no root. A phone uses the in-app data installer (HOW-TO-INSTALL.txt) or assets\sync_phone.ps1 over adb. See docs/05-PHONE-PORT.md.
Real arm64 phones (Android 11+)Fixed Heap pointer tagging is turned off before the server runtime starts. Tested on a Galaxy S24+. See docs/05-PHONE-PORT.md.
Store packs / paid currency offlineWorks The server grants the packs for free and the client skips the payment SDK. The GM panel money buttons work.
Bluetooth gamepad in shooting stagesWorks Move, fire, aim, skills, dodge, pause and auto-fight. Menus still need touch. See docs/11-CONTROLLER.md.
Notice and server-error web pagesWorks The embedded server serves local copies. See docs/08-ONLINE-RESOURCES.md.
Title screensWorks Four titles in rotation (hall, sky, snow, shards); a title whose art does not load is left out. See docs/05-PHONE-PORT.md, section 3.2.
Chapters 13-16 and banners after July 2022Partial The late table set (build 179) starts on a phone up to the title screen; play after login is not checked. See docs/12-LATE-CONTENT.md.
Real online services / multiplayerN/A This is single-player offline only by design. It does not and must not touch official servers.
